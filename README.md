# Knee-d Help · 膝关节居家康复AI训练 Demo

> 香港黑客松演示版：普通摄像头 + 浏览器本地姿态识别。
> 支持**坐站训练**与**仰卧直腿抬高训练**两种康复动作的实时计数、达标判定与错误姿态提示。
> 训练推理无需后端、无需联网、无需 GPU，视频全程不上传。

**核心特性**
- 🏠 左侧导航五模块布局（v5）：首页 / 康复训练 / 训练记录 / 康友圈 / 语音陪伴，单页无刷新
- 🪑 坐站训练（侧面拍摄）：站→坐→站自动计数，膝关节角度检测 / 幅度不足实时提示
- 🛏️ 仰卧直腿抬高训练：放→抬→放自动计数，膝盖弯曲 / 高度不足实时提示
- 🦴 17 点人体骨架实时叠加显示，关键关节角度标注
- 🔊 语音播报计数与错误提示（可关闭），大字体适老化界面
- 👥 实验性多人检测开关（最多 3 人同时计数）
- 📋 训练记录（v5）：每次训练自动保存历史，首页展示连续天数 / 累计次数 / 今日概览
- 💬 朋友圈式康复社群（v4）：训练成果分享、点赞鼓励、文字/语音评论，本地账号模拟
- 🎙️ 双语语音控制（v4）：按住说话即可语音操控训练，支持普通话 / 粤语
- 🗣 LiveKit 多人语音房间（v4，可选）：康复师带练、同伴语音鼓励，断网自动降级模拟语音
- 🛡️ 跌倒检测与模拟报警（v11）：纯摄像头姿态识别三级状态机（快速下坠动力学 + 躺卧姿态 + 肢体节律），全屏高对比倒计时报警弹窗 + 🆘紧急呼救按钮，Demo 演示不实际发送通知
- 🎨 全页面 UI 视觉升级（v12）：暖米白底 + 青绿主色 + 珊瑚橙强调色的适老化设计体系，16px 圆角软阴影卡片、下划线式 Tab、首字圆形头像、分区设置弹窗；仅样式与展示层改动，业务逻辑完全不变
- ☁️ 云端同步 + 训练任务（v13）：自研轻量后端（Node.js + Express + MySQL，见 `server/`，自托管），本地优先/断网可用/联网自动同步；康复师派发训练任务 → 首页任务卡/动作角标/结果卡片进度联动，康复师端表结构与接口已完整预留
- 👩‍⚕️ 康复师端（v14，集成 knee-d-2）：登录身份选择（康复用户/康复师）；康复师工作台——小组管理、按昵称搜索邀请用户、发布单人/小组训练任务（动作/目标达标次数/组数/时间/指定组员）、成员完成情况实时查看（8 秒轮询）；用户完成任务自动关联训练进度，训练记录页显示「完成康复师任务」徽标与任务完成记录区，康复师端同步可见

## 二、快速开始（三步）

**第 1 步：确认收到完整文件**（缺一不可）

```
项目文件夹/
├── index.html          ← 页面（单文件）
├── yolo11n-pose.onnx   ← AI 姿态模型（约 12MB）
├── ort/                ← 推理运行库（5 个文件，约 40MB）
├── server/             ← 云端后端（可选：不部署则纯本地模式运行）
│   ├── app.js / routes/ / middleware/ / utils/
│   ├── sql/init.sql    ← 数据库初始化脚本
│   └── README.md       ← 后端部署与康复师端接入指南
└── README.md
```

**第 2 步：在项目文件夹内启动本地服务器**（推荐方式一）

```bash
cd 项目文件夹
python -m http.server 8000
```

**第 3 步：浏览器打开 http://localhost:8000**

1. 首次打开在**首页**输入昵称完成登录（本地账号，之后自动识别身份；首页用户卡片会显示连续训练天数与累计次数）
2. 浏览器弹出摄像头权限请求时点击**允许**
3. 左侧导航点击「康复训练」→ 选择动作卡片 → 等待状态角标变绿 → 点击「开始训练」
4. 底部导航栏「设置」可开关语音播报、多人检测，切换语音识别语言（粤语/普通话/英语）与界面文字（简体/繁体/英文）

> ⚠️ **不能直接双击 index.html 打开！** 必须通过 `http://localhost` 访问，否则模型加载和摄像头调用都会失败（浏览器安全限制）。

## 三、启动服务器的三种方式（任选其一）

### 方式一：Python（推荐，最通用）

```bash
# Windows / macOS / Linux 通用，Python 3 任意版本
python -m http.server 8000
```

- 未安装 Python：到 [python.org](https://www.python.org/downloads/) 下载安装（Windows 安装时勾选 *Add Python to PATH*）
- 8000 是端口号，被占用时可换成 8080 等任意数字，浏览器地址同步修改

### 方式二：VS Code + Live Server（适合有 VS Code 的人）

1. VS Code 打开项目文件夹
2. 安装扩展 **Live Server**
3. 右键 `index.html` → **Open with Live Server**（会自动开浏览器）

### 方式三：Node.js（适合有 Node 的人）

```bash
npx serve .
# 或
npx http-server -p 8000
```

> 三种方式效果完全相同，只是「用哪个程序把文件以 HTTP 方式发出来」的区别。

## 五、使用指南

### 训练流程

1. 左侧导航进入「康复训练」，选择动作卡片（坐站训练 / 仰卧直腿抬高训练）
2. 等待骨架出现（绿色「准备就绪」角标）
3. 点击**开始训练**（统计清零，开始计时）
4. 按要领完成动作，屏幕实时显示次数与提示
5. 点击**结束训练**，查看结果卡片（总次数、达标率、时长、鼓励文案），可分享到康友圈

### 训练记录

- 每次结束训练自动保存一条记录（日期、动作、完成次数、达标率、时长），存入 localStorage。
- 记录按时间倒序排列，点击卡片可展开查看详情；没有记录时显示空状态提示。
- 首页自动统计：连续训练天数、累计完成次数、今日完成次数与达标率。

### 坐站训练

- **拍摄**：摄像头在**身体正侧面**约 2 米，高度对准膝盖，肩、髋、膝、踝全部入镜；坐在无扶手椅子上，双脚与肩同宽
- **动作**：站起至膝盖伸直（≥160°）→ 完全坐下（≤100°）→ 站起，计 1 次
- **达标**：一次动作同时达到两个角度阈值
- **错误提示**：
  - 只蹲一半就站起 → 「动作幅度不足，请完全坐下再站起」

### 仰卧直腿抬高训练

- **拍摄**：仰卧平躺，摄像头在**身体侧面**约 2 米，肩、髋、膝、踝全部入镜
- **动作**：膝盖伸直，缓慢抬腿至 45° 以上 → 缓慢下放至 20° 以下，计 1 次
- **达标**：抬到 45° + 下放到 20° + 全程膝盖 ≥150°，三者同时满足
- **错误提示**：
  - 膝盖弯曲 <150° → 「请保持膝盖伸直，用大腿发力」
  - 未到 45° 就下放 → 「抬高高度不足，请再往上抬一点」

### 跌倒检测与模拟报警（v11）

- **原理**：仅用现有摄像头姿态识别，无新增硬件、无后端。每帧计算肩髋垂直下坠速度、人体框宽高比（躺卧判定）与膝关节抬放节律，走三级状态机：正常 → 嫌疑（躺卧+快速下坠或躺卧+久静）→ 确认跌倒（嫌疑持续达标）。
- **屏蔽规则**：当且仅当「仰卧直腿抬高训练进行中」完全关闭检测（躺地训练免误报）；结束训练立即恢复。其余页面（首页、选择页、坐站训练、记录、康友圈、设置）全程启用。
- **报警流程**：确认跌倒后弹出全屏红色倒计时弹窗（默认 5 秒，可改 3/5/8/10 秒），语音循环提醒；点击大号「取消报警」退回正常（误触发自动记录）；倒计时结束展示「紧急报警已发送」模拟页（联系人 + 模拟告警内容 + Demo 标注），点击「我已安全」关闭。
- **设置**：底部「设置」→「🛡️ 安全紧急设置」板块：总开关、紧急联系人（姓名/电话）、报警确认时长、检测灵敏度（低/中/高），全部存 localStorage；另有「🆘 紧急呼救（演示）」大按钮，跳过检测直接走完整模拟报警流程。
- **免责声明**：跌倒检测为 AI 辅助识别，存在误判风险，不能替代专业监护设备。

### 云端同步与训练任务（v13）

- **架构**：自研轻量后端 `server/`（Node.js + Express + MySQL，自托管无云依赖）；前端本地优先——数据先写 localStorage，联网后后台静默异步同步，断网/后端不可达时全部功能照常使用，重连自动补传。
- **账号**：登录弹窗新增「本地账号 / 云端账号」切换；云端注册/登录返回 token；「我的」页面可将本地昵称一键「升级云端账号」（设置密码即可，本地 uid 与云端 user_id 保持一致，历史数据自动补传）。
- **训练任务**：康复师（或测试接口）派发任务后，首页「训练任务」卡片展示类型/进度条/截止时间/备注；动作选择页有「待完成任务」角标；每次训练结束自动累加达标次数（同类型多任务优先截止最早、过期不累计、达标自动完成），结果卡片显示「本次训练后已完成 X/XX 次」并高亮「🎉 任务已完成」；进度本地与云端双向同步。
- **隐私边界**：云端只存结构化业务数据（记录摘要/任务/事件/配置/文字动态），视频画面与姿态帧永远只在本机浏览器处理，绝不上传。
- **部署**：见 `server/README.md`（环境要求、数据库初始化、启动步骤、前端 `CFG.API_BASE` 配置、手动创建测试任务的全链路验证方法、康复师端接入指南）。

### 康复师端（v14）

- **入口**：登录弹窗选择「云端账号」→ 登录身份选「康复师」→ 注册（需电话）或登录 → 自动进入独立全屏「康复师工作台」。
- **工作台功能**：
  - 工作台：小组完成情况概览（完成率进度条、需要关注人数）、成员状态表、一键发布任务
  - 我的小组：新建小组、按昵称/名称搜索康复用户并邀请、成员列表、移除成员
  - 训练任务：发布任务（训练小组/动作二选一/目标达标次数/组数要求/训练时间/勾选指定组员），列表展示已分配/已完成人数
  - 成员记录：小组完成率 + 成员完成情况（完成状态/用户备注/完成时间）
- **任务联动闭环**：康复师发布 → 用户首页「康复师下发的训练任务」即时可见（8 秒轮询）→「去完成」直达对应训练 → 训练结束自动累加达标次数 → 达标自动完成 → 训练记录页显示「🏅 完成康复师任务」徽标与「任务完成记录」区 → 康复师端同步看到 1/1 完成。也可在任务卡手动「标记完成」（兜底）。
- **测试账号**：无现成康复师账号时，用云端注册页以「康复师」身份注册一个即可；后端接口自测 `node server/test-v14.cjs`（34 项全链路断言）。

## 六、常见问题排查

| 现象 | 处理 |
|---|---|
| 左上角红色「模型加载失败」 | ① 确认 `yolo11n-pose.onnx` 与 index.html 同目录；② 确认是通过 `http://localhost:8000` 打开（不是双击文件）；③ 确认 `ort/` 目录完整；④ 把页面红框里的「错误详情」发给开发者 |
| 左上角红色「ONNX Runtime 库加载失败」 | `ort/ort.min.js` 缺失或损坏，重新解压完整包 |
| 无法打开摄像头 | 浏览器地址栏左侧允许摄像头权限 → 点「重试」；检查摄像头是否被微信/腾讯会议等占用；必须用 localhost 或 HTTPS 访问 |
| 一直「未检测到人体，请调整位置」 | 光线充足；全身入镜（约 2 米距离）；衣服与背景颜色有对比；参考页面上方的拍摄提示 |
| 计数不灵敏 | 幅度要做满：坐站必须到 100°/160° 两端；直腿抬高必须过 45° 且完全下放 |
| 语音不播报 | 先点一下页面任意按钮（浏览器要求用户交互后才允许发声）；确认「语音播报」已勾选 |
| 页面还是旧版 | **Ctrl+F5 强制刷新**；页脚应显示 **v14** 字样 |
| 手机能不能用 | 可用手机浏览器访问，但仰卧动作的手机机位摆放较困难，演示建议用电脑 |

## 七、给开发者

> 完整技术文档（数据库设计、姿态识别原理、跌倒检测算法、前后端模块实现、云端同步链路）见下方 **「九、技术架构与实现原理」**。

### 可调参数

所有判定阈值与功能开关集中在 `index.html` 顶部 `CFG` 常量：站立/坐态角度、抬起/下放角度、膝盖伸直阈值、平滑帧数（5）、推理帧间隔（2）、社群/语音控制/LiveKit 开关与密钥等，改一处即可生效。

### 更新页面后记得加缓存版本号

`index.html` 中 `ort/ort.min.js?v=9` 的 `?v=9` 用于强制刷新浏览器缓存，**每次修改页面后递增该数字**（页脚版本标记同步更新），否则他人可能打开缓存的旧页面。

### 重新导出模型（一般不需要）

```bash
# 本机 Anaconda 环境旧版 MSVC DLL 会导致 onnx 崩溃，
# export_model.py 已内置 libs/ 新版运行库预加载修复
python export_model.py   # 生成 yolo11n-pose.onnx（opset=12 + simplify）
```

模型固定约定：输入 `images [1,3,640,640]` NCHW，输出 `output0 [1,56,8400]`（4 框 + 1 置信度 + 51 关键点，坐标为 640 输入空间绝对像素，已含解码）。

## 八、v4/v5 新增功能使用说明

### 1. 康友圈

- **入口**：左侧导航「💬 康友圈」或首页大卡片；训练结束的结果卡片点「📤 分享到康友圈」可直接把训练成果发布为动态。
- **账号（全局）**：打开页面即先注册昵称，用于训练记录、社群互动与语音房间身份（存于浏览器 localStorage），下次打开自动登录；页面头部与社群顶部都会显示当前昵称。社群功能未登录到账号时不会出现，账号是全局唯一的。
- **发布动态**：文字输入后点「发布」；或按住「🎤 按住说话」用粤语/普通话说一段话，松开自动转成文字，可编辑后再发布。点「🖼️ 图片」可从本地选图（每条最多 3 张），图片经 canvas 压缩后与文字/语音组合成同一条动态展示。
- **互动**：每条动态可「👍 鼓励」点赞；评论区默认直接展开，支持文字或按住说话评论。
- **个人主页（v7）**：左侧导航「👤 我的」进入个人主页，展示昵称、训练统计与我的动态数，支持「✏️ 修改昵称」；点击头像可从本地选图压缩后设为自定义头像，全站头像即时同步。
- **预置氛围**：代码内置 6 条模拟同伴动态（不同昵称、训练成果与文案），与自己的动态混合按时间倒序展示。`CFG.COMMUNITY_SEED` 可关闭。
- **数据说明**：动态/评论/点赞存 localStorage（`kneed_*` 键），换浏览器或清缓存即丢失，属 Demo 级本地模拟；接入 Supabase 等后端时只需替换代码中 `Store` 存储层实现。

### 9.2 姿态识别原理（模型与推理）

**模型**：`yolo11n-pose.onnx`（YOLO11n-pose，约 11.8MB），ultralytics 标准 ONNX 导出（已含坐标解码）。

| 项 | 约定 |
|---|---|
| 输入 | `[1, 3, 640, 640]` NCHW |
| 输出 | `[1, 56, 8400]`：前 4 通道=边界框 xywh（640 坐标系绝对像素）、第 5 通道=人体置信度（已过 sigmoid）、后 51 通道=17 个 COCO 关键点 ×(x, y, 置信度) |

**推理管线**（每 2 帧一次，30fps 视频下约 15Hz 有效更新率）：

1. **预处理**：视频帧等比缩放 + 灰边填充（letterbox）到 640×640，转 float32
2. **session.run**：ORT Web WASM（本地 `ort/` 目录，单线程，无需跨域隔离）
3. **后处理**：按 `BOX_CONF=0.4` 过滤 → NMS（IoU 0.6）→ 坐标反算回原视频像素系
4. **人物跟踪**：按边界框 IoU 与上一帧匹配（阈值 0.25），连续 45 帧未出现则移除；多人开关下最多跟踪 3 人
5. **关键点平滑**：`KptSmoother` 对最近 5 帧做移动平均（低置信度点不参与该点平均），消除抖动

**角度计算**：`angle3(a,b,c)` 三点向量夹角（0~180°）；膝关节角 = 髋-膝-踝夹角，抬起角 = 180° − 肩-髋-膝夹角。

**两个动作状态机**：

- **坐站训练** `SitStandAnalyzer`：站立(≥160°)→下蹲→坐下(≤100°)→站起为一个计数周期，迟滞边界 150° 防抖动；只蹲一半就站起判「幅度不足」（135° 分界）
- **仰卧直腿抬高** `LegRaiseAnalyzer`：下放(≤20°)→抬起(≥45°)→下放为一个周期；全程膝角 ≥150° 否则提示「保持膝盖伸直」；左右侧取置信度较高的一侧，偏好锁定防跳变

### 9.3 跌倒检测算法（FallDetect，v11）

**三级状态机**：`IDLE → SUSPECT → CONFIRMED`，每帧由推理循环调用 `onFrame()`：

| 检测项 | 实现 |
|---|---|
| 业务屏蔽（最高优先级） | 当且仅当「仰卧直腿抬高训练进行中」完全关闭；其余页面全程启用 |
| 动力学下坠 | 肩(5,6)髋(11,12)平均 Y 位移 / 人体框高 > `FALL_DROP_DY`(0.16，按灵敏度缩放) 记 1 帧下坠；连续 4 帧或 2.5s 窗口内视为下坠证据；平稳时逐帧衰减 |
| 躺卧判定 | 人体框 宽/高 > 1.15（正常坐姿高>宽不触发）；宽/高 < 1.0 视为起身 |
| 肢体节律 | 4s 窗口内膝角摆动幅度 ≥25° 且方向翻转 ≥2 峰 → 判定主动训练，抑制嫌疑 |
| 久静 | 无有效肢体活动（起身/大幅位移/节律均算活动）持续 8s（灵敏度缩放） |
| 置信度校验 | 17 点平均置信度 < 0.5 不做判定（防遮挡误判） |
| 状态流转 | 躺卧 +（下坠 或 久静）→ SUSPECT 启动风险计时 → 持续达标 6s → CONFIRMED 触发报警弹窗；起身/大幅活动立即回 IDLE；部分满足仅语音预警不报警 |
| 边界场景 | 训练后躺卧休息正常计时；缓慢滑倒由「躺卧+久静」捕获；清醒躺卧由大号取消按钮撤销（误触发记入本地并上报云端） |

### 9.4 前端重点模块实现

- **CFG**：全局配置中心，所有可调参数（模型/阈值/跌倒/云端/模块开关）集中于此，顶部注释即文档
- **Store**：localStorage 封装（JSON 序列化、不可用时降级内存、`quotaOk` 配额预检保护语音/图片存储）
- **CloudSync（v13）**：
  - token 存 localStorage；请求 4s 超时视为离线
  - 待同步队列 `cloudPending`：失败重试 3 次 → 移入 `cloudFailed` 待下次触发；触发时机 = 每次写入后 / 登录后 / `online` 事件 / 8s 轮询
  - `pullAll` 拉取合并：任务/小组按 ID 去重、训练记录按 ID 合并（本地优先）、**本地进度领先时保留本地**（防止轮询用云端旧值回退刚训练的进度）
  - 仅同步结构化数据：记录摘要、任务进度、跌倒事件、配置、文字动态（图片 base64 不上传）
- **Tasks（v14，分配制）**：康复师任务 → `user_tasks` 每人一行（个人进度/完成时间/完成记录）。训练结束 `afterTraining`：本地先累加 → 达标置完成并回写训练记录任务标记 → 云端异步同步；同类型多任务截止最早优先、过期不累计、已完成不重复
- **康复师工作台 TP（v14）**：全屏独立视图，8s 轮询任务/成员状态（数据变化才重渲染）；发布任务支持小组全员/勾选组员/单人；患者数据接口按「小组归属」鉴权
- **多语言（v8）**：简/繁用 opencc-js（本地 libs/ + CDN 兜底）；英文用 L10N_EN 字典（长串优先）+ 参数化正则（如 `本次训练后，「X」任务已完成 N/M 次`）；静态文本 walker 遍历 + `srcTexts` WeakMap 记录源文本保证往返切换不漂移；动态容器（JS 写值）在 `DYNAMIC_TEXT_SELECTORS` 清单内由各渲染函数重设
- **语音**：Web Speech API（识别 `SpeechRecognition` + 合成 `SpeechSynthesis`）；界面语言自动映射朗读/识别语言（简→zh-CN、繁→zh-HK、英→en-US），无粤语语音包自动降级普通话；语音控制走关键词指令表（长关键词优先匹配）
- **LiveKit 语音房间**：SDK 加载失败/未配密钥/连接超时自动降级「模拟语音演示」（预置台词 + TTS），保证演示不断档

### 9.5 后端实现要点

- **鉴权**：`jsonwebtoken` 签发（用户 7 天 / 康复师 12 小时，payload 带 role）；`auth` 与 `therapistAuth` 两级中间件；密码 bcrypt（10 轮）哈希，全程无明文
- **幂等设计**：训练记录/跌倒事件/任务分配/社群动态均以客户端生成 ID 为主键，`INSERT IGNORE` 防重复上报（离线补传重试安全）
- **任务进度事务**（`POST /api/tasks/update-progress`）：惰性过期（deadline 已过 → status=3）→ 匹配「待完成、同类型、未过期」分配行按截止最早 → 累加达标次数 → 达标则置完成 + 记录 `completed_at/completed_record_id` + **回写训练记录 `task_id/task_completed`**（训练记录页与康复师端可见的落点）→ 更新任务聚合状态（完成人数）
- **权限模型**：康复师仅可访问自己小组内成员（`requirePatient` 403 拦截）；`therapists/patient_therapist_relation/therapist_remarks` 三表为医院体系预留
- **统一规范**：`{code, message, data}` 响应、全局错误处理、全接口参数校验（`utils/validate.js`）、CORS 中间件、404/501 规范

### 9.7 云端同步数据流（一条训练记录的完整旅程）

```
结束训练
  │ ① 本地先写：Store.push('records') —— 离线也可用
  │ ② Tasks.afterTraining：本地任务进度先累加（达标→完成态+完成记录链）
  │ ③ CloudSync 入队（cloudPending）：[record 上传] → [任务进度]
  ▼
后端 /api/training/upload（幂等） 与 /api/tasks/update-progress（事务）
  │ ④ 任务达标：回写 training_records.task_id/task_completed
  ▼
MySQL 三表一致：records + training_tasks(聚合) + user_tasks(个人)
  │ ⑤ 前端 8s 轮询 /api/tasks + /api/my_groups 合并（本地领先保护）
  ▼
UI 全链路可见：训练记录「🏅完成康复师任务」徽标 + 任务完成记录区
              ← 康复师工作台成员状态 ✅（另一浏览器 8s 内同步）
```

断网时 ③~⑤ 全部挂起在本地队列，重连自动补传；`cloudFailed` 记录最终失败项待下次重试。
